**问题：**
- `core-sdk/tsconfig.json` 第 12 行：`noImplicitAny: false` — 允许隐式 `any`，削弱类型安全
- `core-sdk/tsconfig.json` 第 14 行：`strictFunctionTypes: false` — 函数参数逆变检查被禁用
- `core-sdk/tsconfig.json` 第 15 行：`strictPropertyInitialization: false` — 属性初始化检查被禁用
- `siwe`、`siwx`、`passkey-auth`、`social-login` 均有 `noImplicitAny: false`

#### 错误处理

**优点：**
- `core-sdk/src/errors/` 目录有完整的错误系统：错误码定义 (`codes.ts`)、错误类 (`classes.ts`)、i18n (`i18n.ts`)、工具函数 (`utils.ts`)
- 错误分类清晰：CONNECTION、AUTHENTICATION、CHAIN、TRANSACTION、WALLET_CONNECT、SIGNING、NETWORK、SDK、SECURITY
- 支持错误序列化/反序列化 (`errorToJSON`/`errorFromJSON`)
- 支持多语言翻译

**问题：**
- `siwx/src/verifier-registry.ts` 第 180-210 行：所有加密原语（`recoverAddressEvm`、`verifyEd25519`、`verifyBip322`）均为 stub，直接 `throw new Error('Not implemented')` — 这意味着 **所有跨链签名验证实际上不工作**
- `siwx/src/siwx.ts` 第 4 行：`import { randomBytes } from 'crypto'` — 使用 Node.js `crypto` 模块，在浏览器环境中不可用

#### 代码重复度

- `adapters/metamask/utils.ts` 和 `adapters/coinbase/utils.ts` 和 `adapters/phantom/utils.ts` 均导出 `toHexChainId`/`fromHexChainId` — 应提取到共享工具包
- `core-sdk/src/connector.ts` 和 `core-sdk/src/session.ts` 在同一文件中定义了两个独立类（`RedirectHandler` + `Connector` 和 `SessionManager` + Store），文件职责不够单一
- `core-sdk/src/index.ts` 中 `CinacoinError` 被重复导出两次（第 157 行和第 192 行）

#### 类型完整性

- `core-sdk/src/types.ts`：类型定义完整，CAIP 类型正确 re-export
- `siwx/src/types.ts`：`ChainType` 仅支持 5 种链，扩展需要修改类型定义
- `session-keys/src/types.ts`：`SessionKey` 包含 `privateKey` 字段在类型中 — 存在泄漏风险

### 2.2 架构设计

#### 模块耦合度

**优点：**
- `Connector` 抽象类设计良好，所有 transport 继承它
- `EventEmitter` 轻量级实现，无外部依赖
- `SessionManager` 状态机模式清晰（disconnected → connecting → connected → disconnected）
- `SIWXRegistry` 和 `VerifierRegistry` 使用注册表模式，支持扩展
- CAIP 包完全独立，无外部依赖

**问题：**
- `core-sdk/src/session.ts` 文件过大（~300 行），混合了 `SessionManager` 和 Zustand Store — 应拆分
- `core-sdk/src/index.ts` 过于庞大（~250 行），导出过多内容 — 建议使用 barrel files 分模块
- `social-login/src/social-wallet.ts` 直接依赖 `embedded-wallet-shim.ts` 内部实现 — 耦合过紧
- `siwx` 包同时包含消息创建、签名验证、会话管理、React hooks — 职责过多

#### 接口设计

**优点：**
- `Connector` 接口统一：connect/disconnect/getAccounts/getChainId/switchChain/signMessage/signTransaction
- `EIP5792Client` 最小接口设计，兼容任何 JSON-RPC provider
- `SIWEProvider` 支持 viem/ethers v5/v6/EIP-1193 三种 provider 类型
- `PasskeyStorage` 接口可替换存储后端

**问题：**
- `Connector.getProvider()` 返回 `unknown` — 类型不安全（`core-sdk/src/connector.ts` 第 107 行）
- `createAdapter()` 函数返回 `Promise<unknown>` — 丢失类型信息（`core-sdk/src/index.ts` 第 218 行）
- `QRTransport.connect()` 总是 reject（`core-sdk/src/transports/qr.ts` 第 117 行）— 功能未完成

#### 扩展性

- `SIWXRegistry` 支持注册自定义链适配器 ✅
- `VerifierRegistry` 支持注册自定义验证器 ✅
- `SessionKeyPolicyManager` 支持预设策略（DEX、NFT Mint） ✅
- `chain-registry` 支持运行时动态注册链 ✅
- 缺少插件系统或中间件机制

#### 依赖方向

- 依赖方向总体正确：底层包（caip、logger）无上层依赖
- `@cinacoin/logger` 被广泛依赖但未见其源码审计
- `viem` 作为 `session-keys` 的硬依赖（非 peer dependency）— 增加 bundle size

### 2.4 安全性

#### 🔴 Critical

1. **SIWX 加密验证全部为 Stub**
   - 文件：`siwx/src/verifier-registry.ts` 第 180-210 行
   - 问题：`recoverAddressEvm()`、`verifyEd25519()`、`verifyBip322()` 均直接 throw
   - 影响：**所有跨链签名验证不工作**，生产环境中无法验证 Solana/Bitcoin/TON/TRON 签名
   - 建议：实现真正的加密验证或明确标记为 alpha/不可用

2. **Session 完整性检查使用非密码学哈希**
   - 文件：`core-sdk/src/session.ts` 第 56-62 行
   - 问题：`computeIntegrity()` 使用 djb2-like 哈希（32-bit 整数），非密码学安全
   - 影响：攻击者可轻易伪造 session 数据
   - 建议：使用 `crypto.subtle.digest('SHA-256', ...)` 或 HMAC

3. **Social Login 钱包派生密钥可预测**
   - 文件：`social-login/src/wallet-derivation.ts` 第 30-40 行
   - 问题：`deriveSeedFromIdentity()` 使用 HKDF 但 info 参数默认为 `'cinacoin-default'`
   - 影响：如果攻击者知道用户的 providerId 和 identifier，可以推导出相同的私钥
   - 建议：添加服务端 secret 作为必需参数；使用硬件安全模块存储 master key

#### 🟠 High

4. **QR Transport 对称密钥明文暴露在 URI 中**
   - 文件：`core-sdk/src/transports/qr.ts` 第 130-135 行
   - 问题：`symKey` 直接拼接到 QR URI 中（`wc:{topic}@2?...&symKey={symKey}`）
   - 影响：QR 码被扫描前可被截屏窃取
   - 建议：使用 ECDH 密钥交换，而非直接暴露对称密钥

5. **Passkey 认证返回空签名数据**
   - 文件：`passkey-auth/src/passkey.ts` 第 95-100 行
   - 问题：`authenticate()` 返回 `signature: ''`、`authenticatorData: ''`、`clientDataJSON: ''`
   - 影响：服务端无法验证 passkey 认证的真实性
   - 建议：从 `PublicKeyCredential.response` 中提取真实签名数据

6. **SIWX 使用 Node.js crypto 模块**
   - 文件：`siwx/src/siwx.ts` 第 4 行
   - 问题：`import { randomBytes } from 'crypto'` — 浏览器环境不可用
   - 影响：SIWX 在浏览器中会崩溃
   - 建议：使用 `globalThis.crypto.getRandomValues()` 或条件导入

7. **Session Key 私钥存储在内存 Map 中**
   - 文件：`session-keys/src/session-key.ts` 第 28 行
   - 问题：`private keys` 存储在 `Map<Address, SessionKey>` 中，无加密保护
   - 影响：内存转储可泄露所有会话密钥
   - 建议：使用 `crypto.subtle` 加密存储；或仅存储加密后的密钥

#### 🟡 Medium

8. **SESSION_SECRET 检查仅在模块加载时执行**
   - 文件：`core-sdk/src/session.ts` 第 34-40 行
   - 问题：仅在 `NODE_ENV === 'production'` 时检查，且只在模块首次加载时执行
   - 建议：在每次 session 操作时验证

9. **SIWE 地址归一化仅使用 toLowerCase**
   - 文件：`siwe/src/utils.ts` 第 65 行
   - 问题：`normalizeAddress()` 仅做小写转换，未实现 EIP-55 checksum 验证
   - 建议：添加 EIP-55 checksum 验证

10. **Verify SDK 使用字符串匹配检测危险函数**
    - 文件：`verify-sdk/src/scanner.ts` 第 50-70 行
    - 问题：使用 `code.includes(pattern)` 检测危险模式，易被注释或字符串绕过
    - 建议：使用 AST 解析而非字符串匹配

11. **Social Login Token 验证缺少 JWK 缓存**
    - 文件：`social-login/src/token-verifier.ts`（未完整审计）
    - 问题：每次验证可能重新获取 JWKS
    - 建议：添加 JWK 缓存层

#### 🟢 Low

12. **EIP-6963 发现窗口固定 300ms**
    - 文件：`core-sdk/src/eip6963.ts` 第 55 行
    - 问题：硬编码 300ms 可能在慢速设备上不够
    - 建议：允许配置发现窗口

13. **RelayTransport 重连无 jitter**
    - 文件：`core-sdk/src/transports/relay.ts` 第 170 行
    - 问题：指数退避无随机 jitter，可能导致 thundering herd
    - 建议：添加随机 jitter

2. **替换 Session 完整性哈希**
   ```typescript
   async function computeIntegrity(state: object): Promise<string> {
     const data = JSON.stringify(state);
     const encoder = new TextEncoder();
     const hash = await crypto.subtle.digest('SHA-256', encoder.encode(data));
     return Array.from(new Uint8Array(hash)).map(b => b.toString(16).padStart(2, '0')).join('');
   }
   ```

3. **Social Login 添加服务端 secret**
   ```typescript
   export function deriveSeedFromIdentity(
     providerId: string,
     identifier: string,
     serverSecret: string  // 必需参数
   ): Uint8Array {
     const salt = new TextEncoder().encode('cinacoin-social-login-v1');
     const ikm = new TextEncoder().encode(`${providerId}:${identifier}`);
     const info = new TextEncoder().encode(serverSecret);
     return hkdf(sha256, ikm, salt, info, 32);
   }
   ```
