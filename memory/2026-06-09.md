## Auth Service 注册登录流程调试 (01:35-02:30 UTC)

### 问题发现与修复

#### 1. JWT_REFRESH_SECRET 缺失
- **问题**: 登录时返回 500 错误
- **原因**: 代码需要 `JWT_REFRESH_SECRET` 环境变量，但只配置了 `JWT_SECRET`
- **修复**: 添加 `JWT_REFRESH_SECRET` 到 wrangler.toml 和 Cloudflare secrets

#### 2. PBKDF2 迭代次数过高
- **问题**: 注册时返回 500 错误
- **日志**: `Pbkdf2 failed: iteration counts above 100000 are not supported (requested 600000)`
- **原因**: Cloudflare Workers Web Crypto API 限制 PBKDF2 最多 100,000 次迭代
- **修复**: 将 `PBKDF2_ITERATIONS` 从 600,000 降至 100,000
- **文件**: `workers/auth-service/src/lib/password.ts`

#### 3. 数据库表结构不完整
- **问题**: 注册时返回 "Failed to register user"
- **原因**: 数据库缺少 `display_name`、`role`、`last_login_at` 列
- **修复**: 执行 ALTER TABLE 添加缺失列
```sql
ALTER TABLE users ADD COLUMN display_name TEXT;
ALTER TABLE users ADD COLUMN role TEXT DEFAULT 'user';
ALTER TABLE users ADD COLUMN last_login_at INTEGER;
```

#### 4. mfa_methods 表缺失
- **问题**: 登录时返回 500 错误
- **日志**: `D1_ERROR: no such table: mfa_methods: SQLITE_ERROR`
- **原因**: 代码引用了 `mfa_methods` 表但迁移文件没有创建它
- **修复**: 手动创建 mfa_methods 表
```sql
CREATE TABLE IF NOT EXISTS mfa_methods (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  type TEXT NOT NULL,
  is_enabled INTEGER NOT NULL DEFAULT 0,
  totp_secret TEXT,
  totp_verified INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

#### 5. sessions 表字段问题
- **问题**: 登录时返回 "Failed to login"
- **原因**: 
  - `refresh_token_hash` 列有 NOT NULL 约束但未插入
  - `created_at` 列是 INTEGER NOT NULL 但未插入
  - `issued_at` 和 `expires_at` 是 TEXT 类型但传入数字
- **修复**: 更新 `token-rotation.ts` 中的 INSERT 语句，添加所有必需字段

#### 6. hashToken 异步调用问题
- **问题**: Token 刷新失败
- **原因**: `hashToken` 是异步函数，但调用时没有 `await`
- **修复**: 在 `rotateRefreshToken`、`detectTokenReuse` 等函数中添加 `await`

#### password.ts - PBKDF2 迭代次数
```typescript
// 修复前

// 修复后

```

#### token-rotation.ts - sessions INSERT 语句
```typescript
// 修复前 - 缺少 refresh_token_hash 和 created_at
await db.prepare(
  `INSERT INTO sessions (id, user_id, token_family, token_hash, token_type, issued_at, expires_at, ip_address, user_agent)
   VALUES (?, ?, ?, ?, 'refresh', ?, ?, ?, ?)`
).bind(...);

// 修复后 - 添加所有必需字段
await db.prepare(
  `INSERT INTO sessions (id, user_id, token_family, token_hash, refresh_token_hash, token_type, issued_at, expires_at, ip_address, user_agent, created_at)
   VALUES (?, ?, ?, ?, ?, 'refresh', ?, ?, ?, ?, ?)`
).bind(
  uuidv4(),
  userId,
  familyId,
  tokenHash,
  tokenHash,
  issuedAt,      // ISO 字符串
  expiresAt,     // ISO 字符串
  metadata?.ipAddress || null,
  metadata?.userAgent || null,
  Date.now()     // created_at 时间戳
);
```

#### token-rotation.ts - hashToken 异步调用
```typescript
// 修复前
const oldTokenHash = hashToken(oldToken);

// 修复后
const oldTokenHash = await hashToken(oldToken);
```

### 经验教训

1. **Cloudflare Workers 限制**: Web Crypto API 的 PBKDF2 迭代次数上限是 100,000，不是 OWASP 推荐的 600,000
2. **数据库迁移**: 代码和数据库表结构必须严格同步，缺少字段会导致运行时错误
3. **异步函数**: 必须检查函数签名，确保异步函数使用 `await` 调用
4. **日志调试**: `wrangler tail` 是调试 Cloudflare Workers 的关键工具
5. **限流清理**: 测试时频繁触发限流，需要定期清理 KV 中的限流记录

## Auth Service 注册登录流程调试 (01:35-02:30 UTC)

### 问题发现与修复

#### 1. JWT_REFRESH_SECRET 缺失
- **问题**: 登录时返回 500 错误
- **原因**: 代码需要 `JWT_REFRESH_SECRET` 环境变量，但只配置了 `JWT_SECRET`
- **修复**: 添加 `JWT_REFRESH_SECRET` 到 wrangler.toml 和 Cloudflare secrets

#### 2. PBKDF2 迭代次数过高
- **问题**: 注册时返回 500 错误
- **日志**: `Pbkdf2 failed: iteration counts above 100000 are not supported (requested 600000)`
- **原因**: Cloudflare Workers Web Crypto API 限制 PBKDF2 最多 100,000 次迭代
- **修复**: 将 `PBKDF2_ITERATIONS` 从 600,000 降至 100,000
- **文件**: `workers/auth-service/src/lib/password.ts`

#### 3. 数据库表结构不完整
- **问题**: 注册时返回 "Failed to register user"
- **原因**: 数据库缺少 `display_name`、`role`、`last_login_at` 列
- **修复**: 执行 ALTER TABLE 添加缺失列
```sql
ALTER TABLE users ADD COLUMN display_name TEXT;
ALTER TABLE users ADD COLUMN role TEXT DEFAULT 'user';
ALTER TABLE users ADD COLUMN last_login_at INTEGER;
```

#### 4. mfa_methods 表缺失
- **问题**: 登录时返回 500 错误
- **日志**: `D1_ERROR: no such table: mfa_methods: SQLITE_ERROR`
- **原因**: 代码引用了 `mfa_methods` 表但迁移文件没有创建它
- **修复**: 手动创建 mfa_methods 表
```sql
CREATE TABLE IF NOT EXISTS mfa_methods (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  type TEXT NOT NULL,
  is_enabled INTEGER NOT NULL DEFAULT 0,
  totp_secret TEXT,
  totp_verified INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

#### 5. sessions 表字段问题
- **问题**: 登录时返回 "Failed to login"
- **原因**: 
  - `refresh_token_hash` 列有 NOT NULL 约束但未插入
  - `created_at` 列是 INTEGER NOT NULL 但未插入
  - `issued_at` 和 `expires_at` 是 TEXT 类型但传入数字
- **修复**: 更新 `token-rotation.ts` 中的 INSERT 语句，添加所有必需字段

#### 6. hashToken 异步调用问题
- **问题**: Token 刷新失败
- **原因**: `hashToken` 是异步函数，但调用时没有 `await`
- **修复**: 在 `rotateRefreshToken`、`detectTokenReuse` 等函数中添加 `await`

### 经验教训

1. **Cloudflare Workers 限制**: Web Crypto API 的 PBKDF2 迭代次数上限是 100,000，不是 OWASP 推荐的 600,000
2. **数据库迁移**: 代码和数据库表结构必须严格同步，缺少字段会导致运行时错误
3. **异步函数**: 必须检查函数签名，确保异步函数使用 `await` 调用
4. **日志调试**: `wrangler tail` 是调试 Cloudflare Workers 的关键工具
5. **限流清理**: 测试时频繁触发限流，需要定期清理 KV 中的限流记录

## Auth Service 注册登录流程调试 (01:35-02:30 UTC)

### 问题发现与修复

#### 1. JWT_REFRESH_SECRET 缺失
- **问题**: 登录时返回 500 错误
- **原因**: 代码需要 `JWT_REFRESH_SECRET` 环境变量，但只配置了 `JWT_SECRET`
- **修复**: 添加 `JWT_REFRESH_SECRET` 到 wrangler.toml 和 Cloudflare secrets

#### 2. PBKDF2 迭代次数过高
- **问题**: 注册时返回 500 错误
- **日志**: `Pbkdf2 failed: iteration counts above 100000 are not supported (requested 600000)`
- **原因**: Cloudflare Workers Web Crypto API 限制 PBKDF2 最多 100,000 次迭代
- **修复**: 将 `PBKDF2_ITERATIONS` 从 600,000 降至 100,000
- **文件**: `workers/auth-service/src/lib/password.ts`

#### 3. 数据库表结构不完整
- **问题**: 注册时返回 "Failed to register user"
- **原因**: 数据库缺少 `display_name`、`role`、`last_login_at` 列
- **修复**: 执行 ALTER TABLE 添加缺失列
```sql
ALTER TABLE users ADD COLUMN display_name TEXT;
ALTER TABLE users ADD COLUMN role TEXT DEFAULT 'user';
ALTER TABLE users ADD COLUMN last_login_at INTEGER;
```

#### 4. mfa_methods 表缺失
- **问题**: 登录时返回 500 错误
- **日志**: `D1_ERROR: no such table: mfa_methods: SQLITE_ERROR`
- **原因**: 代码引用了 `mfa_methods` 表但迁移文件没有创建它
- **修复**: 手动创建 mfa_methods 表
```sql
CREATE TABLE IF NOT EXISTS mfa_methods (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  type TEXT NOT NULL,
  is_enabled INTEGER NOT NULL DEFAULT 0,
  totp_secret TEXT,
  totp_verified INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

#### 5. sessions 表字段问题
- **问题**: 登录时返回 "Failed to login"
- **原因**: 
  - `refresh_token_hash` 列有 NOT NULL 约束但未插入
  - `created_at` 列是 INTEGER NOT NULL 但未插入
  - `issued_at` 和 `expires_at` 是 TEXT 类型但传入数字
- **修复**: 更新 `token-rotation.ts` 中的 INSERT 语句，添加所有必需字段

#### 6. hashToken 异步调用问题
- **问题**: Token 刷新失败
- **原因**: `hashToken` 是异步函数，但调用时没有 `await`
- **修复**: 在 `rotateRefreshToken`、`detectTokenReuse` 等函数中添加 `await`

```typescript
// 修复后 - 添加所有必需字段
await db.prepare(
  `INSERT INTO sessions (id, user_id, token_family, token_hash, refresh_token_hash, token_type, issued_at, expires_at, ip_address, user_agent, created_at)
   VALUES (?, ?, ?, ?, ?, 'refresh', ?, ?, ?, ?, ?)`
).bind(
  uuidv4(),
  userId,
  familyId,
  tokenHash,
  tokenHash,
  issuedAt,      // ISO 字符串
  expiresAt,     // ISO 字符串
  metadata?.ipAddress || null,
  metadata?.userAgent || null,
  Date.now()     // created_at 时间戳
);
```

#### token-rotation.ts - hashToken 异步调用
```typescript
// 修复前
const oldTokenHash = hashToken(oldToken);

// 修复后
const oldTokenHash = await hashToken(oldToken);
```

### 经验教训

1. **Cloudflare Workers 限制**: Web Crypto API 的 PBKDF2 迭代次数上限是 100,000，不是 OWASP 推荐的 600,000
2. **数据库迁移**: 代码和数据库表结构必须严格同步，缺少字段会导致运行时错误
3. **异步函数**: 必须检查函数签名，确保异步函数使用 `await` 调用
4. **日志调试**: `wrangler tail` 是调试 Cloudflare Workers 的关键工具
5. **限流清理**: 测试时频繁触发限流，需要定期清理 KV 中的限流记录

### 🔴 紧急问题：Website 客户端崩溃

**现象**: cinacoin.com 显示 "Something went wrong" 错误
**诊断**:
- SSR 内容正常（curl 返回完整 HTML）
- 客户端 hydration 崩溃

**根因**: `I18nProvider` 中的 `initialLocale` 在模块加载时计算（`const initialLocale = getInitialLocale()`），导致：
- SSR 时 `typeof window === 'undefined'`，返回 `'en'`
- 客户端 hydration 时 `window` 存在，可能返回 `'zh'`（如果浏览器语言是中文）
- 这导致 SSR 和客户端初始渲染不一致，触发 hydration mismatch 错误

**修复方案**: 将 `I18nProvider` 改为始终在 SSR 和客户端初始渲染时使用 `'en'`，然后在 `useEffect` 中更新为实际语言偏好。类似 `ThemeProvider` 的 `mounted` 模式。

**状态**: ⚠️ 修复代码已准备好，但因内存刷新限制未能写入文件。需要在下次会话中执行修复。

```typescript
const initialLocale = getInitialLocale()  // 模块级别计算

export function I18nProvider({ children }: { children: React.ReactNode }) {
  const [locale, setLocaleState] = useState<Locale>(initialLocale)
  // ...
}

// 修复后
export function I18nProvider({ children }: { children: React.ReactNode }) {
  const [locale, setLocaleState] = useState<Locale>('en')  // 始终 'en' 匹配 SSR
  const [mounted, setMounted] = useState(false)

  useEffect(() => {
    const clientLocale = getInitialLocale()
    setLocaleState(clientLocale)
    setMounted(true)
  }, [])

  useEffect(() => {
    if (!mounted) return
    try { localStorage.setItem('cc-locale', locale) } catch {}
    document.documentElement.lang = locale
  }, [locale, mounted])
  // ...
}
```

### 经验教训
1. Next.js 静态导出中，所有客户端状态必须在 `useEffect` 中初始化，不能在模块级别或 `useState` 初始值中访问浏览器 API
2. `ThemeProvider` 已经正确使用了 `mounted` 模式，但 `I18nProvider` 没有遵循相同模式
3. SSR hydration mismatch 会静默导致 React 客户端错误，显示 "Something went wrong"
