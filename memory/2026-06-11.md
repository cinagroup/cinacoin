## Login Page Design System Fix
- Fixed login page at /login to comply with design.md and UI.md guidelines
- **Root cause**: Tailwind config and shared-design-system.css used hardcoded font-family instead of CSS variables from layout.tsx
- **Fixes applied**:
  - Updated `design-system/tailwind-preset.ts`: fontFamily.sans now uses `var(--font-geist-sans)` 
  - Updated `apps/unified-dashboard/src/shared-design-system.css`: --font-sans and --font-mono now use CSS variables
  - Rewrote login page using proper cc-* component classes (cc-caption-mono, cc-display-sm, cc-form-input, cc-btn-primary)
- **Design compliance**:
  - Mono eyebrow: "AUTHENTICATION" using cc-caption-mono
  - Sentence case + period: "Log in to your account."
  - Geist font properly applied via CSS variables
  - Form inputs use cc-form-input with proper focus states
  - Button uses cc-btn-primary
- **Deployment**: https://6e90b97f.cinacoin-unified-dashboard.pages.dev
- **Production URL**: https://app.cinacoin.com/login

## Key Lesson Learned
- Tailwind config must reference CSS variables from layout.tsx for custom fonts to work
- Always use cc-* component classes from shared-design-system.css instead of raw Tailwind utilities
- Font loading order: layout.tsx creates CSS variables → shared-design-system.css references them → Tailwind uses them
